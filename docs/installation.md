# 隔离安装与回退

版本：0.1.0-draft.2；仍是试用草案。初始报告中的“未安装”是历史交付状态，不是每台机器的实时安装状态。

## 为什么改名

原先主技能引用兄弟目录`html-mockup`，在已有同名技能的客户端会冲突；仅安装主技能还可能误读旧工具。本版将配套改为独立目录与frontmatter名称：

```text
$CODEX_HOME/skills/          # 未设置时使用 ~/.codex/skills/
  html-mockup/               # 已有用户技能，完全保留
  ai-project-kickoff/        # 本次新增主技能
  ai-project-kickoff-html-mockup/  # 本次新增独立配套
```

主技能通过相对链接明确读取独立配套。不是覆盖、软链替换或复制后修改安装文件；安装字节与GitHub固定commit一致。两份技能需同版；本版不对外发布旧目录的兼容别名，以免重新抢占旧技能。

## 安装步骤

1. 核对当前授权、Codex实际HOME/CODEX_HOME和已存在目标；不默认安装到Claude、其他设备或其他用户。
2. 如任一新目标已存在，先停止，核对其来源/改动；不得直接覆盖。旧html-mockup无需移动、升级或重命名。
3. 从GitHub取得并核对完整commit；使用当前客户端的skill-installer官方脚本，以该commit而不是可移动main为ref，一次指定两个路径：`skills/ai-project-kickoff`和`skills/ai-project-kickoff-html-mockup`。不在公开仓库硬编码本机用户名或私有安装器路径。
4. 安装后核对所有文件与固定commit的哈希、两份格式和主技能→配套的实际路径；旧技能符号链接和源文件哈希必须保持。
5. 安装记录保存在本机受控记录中，写版本/commit/目录/校验结果；笔记只留摘要，不上传其他技能或密钥。
6. 下一轮可使用`$ai-project-kickoff`。文件已安装不等于已证明客户端每次会自动选择；若当前客户端列表未刷新，重新打开会话或按该客户端实际刷新方式处理。

安装结果不明先检查两个目录，不重复安装。安装器报目标存在时不是“已成功升级”。只有文件/引用核验通过才能报告安装完成；本机安装不代表其他机器已安装。

## 使用与回退

> 使用 $ai-project-kickoff。我准备做……。先按三档自适应完成启动方案，用专用HTML配套汇报并归档，不自行部署或调用付费服务。

本次新增目录之前不存在，因此无需备份并替换旧技能。规则变动前的源码基线仍需备份；旧html-mockup只记录链接与文件清单哈希，不修改其内容。
要撤销安装时，先核对安装记录及两个新目录是否有后续用户改动，再仅移出本次新增的两个目录；不删除或重置旧html-mockup、不改全局AGENTS入口。若一半失败，记录哪一份已安装并先核对，不把部分安装说成全部可用。

## 验证范围

新增隔离布局回归检查：模拟同一技能目录已有旧html-mockup，安装两份新技能后检查引用只指向独立配套、旧文件不变及名称一致；不以格式检查替代真实安装与哈希核对。原有流程/HTML工具能力和真实业务限制不因改名而改变。
