02 三档不是三套流程：同一路线，不同证据深度

档位典型项目必须保留允许精简
轻量低风险个人工具、内容站、单点探索目标/范围、HTML、验收和资料入口、授权边界资料合页，不造无需求的登录/数据库/后台。
标准普通新产品、团队协作、常规集成主流程与异常、规则权限、关键架构/契约、任务测试、运维准备按模块合并，不强求文件数量或某个技术栈。
高风险资金/敏感数据/高影响权限、不可逆变更、关键离线交易和外设标准内容 + 风险spike、幂等/结果核对、恢复与相应实测可缩业务范围，不能删适用安全证据或把模拟当真实验收。
识别上下文头脑风暴/调研MVP与规则原型与架构迭代任务/真实切片验证与运维交接

平台、风险档位、交付目标分别判断：高风险项目也可以只做方案；默认标准，发现高风险升级，不因赶工降档。架构、原型和风险探索互相校正，不僵化成瀑布审批。

04 原型、架构、运维放在哪：位置与维护责任一起写

PROJECT ARCHIVE
  docs/index.md
  docs/project/status.md            -> one current status source
  docs/research/                    -> source + date + selection
  docs/product/                     -> scope + rules + acceptance
  docs/design/prototypes/<feature>/
    index.md                        -> version + review index
    source/index.html               -> editable canonical artifact
    snapshots/                      -> verified visual states
    reviews/                        -> feedback + decisions
  docs/architecture/decisions/       -> ADR + consequences + exit
  docs/data/ + docs/api/             -> source/schema references
  docs/testing/                     -> evidence + limitations
  docs/operations/                  -> deploy + migrate + restore + alert
  docs/releases/ + docs/ai/handoff.md

DISPLAY COPY
  preview_html / authorized existing server
  same archived version; not the only copy

已有项目保留原目录并建映射，不自动搬家或创建一堆空文件。每类资料写维护者、何时更新和唯一来源；schema/API/迁移仍以对应源码或契约为准。

运维不只部署命令，还包括环境、制品身份、兼容迁移、代码回滚与数据恢复的区别、数据库/文件备份、RPO/RTO与恢复实测、监控告警、故障责任、升级和停服。
