# 资料放置、持续维护与运维交接

本篇是本技能内资料位置、文档维护和运维准备的详细来源；原型细节见 [原型与设计](prototypes-and-design.md)。
适用新项目启动、现有项目接手与交付准备；按项目规模裁剪，不要求一开始写满所有文档。
本文件属于技能草案，不授权安装、提交、部署、数据库迁移、公开服务或远端同步。

## 1. 先找已有事实，再补缺口

- 先读取任务路径上的 `AGENTS.md`、项目入口、已有文档和源码布局。
- 核对仓库、分支、工作树、已知环境及当前任务授权，保留已有修改。
- 现有项目沿用已有文档位置，在入口建“建议分类 → 实际路径”的映射。
- 不为了统一目录搬文件、改入口、合并规则或创建与现有文档冲突的副本。
- 新项目采用下面的建议结构；仅在有实际内容和维护需求时创建文件。
- 每份重要资料有负责人或负责角色、状态、更新时间、适用版本和事实来源。
- `AGENTS.md` 放项目执行边界和导航；不要塞成长篇架构、运维教程或多份重复规则。
- `README.md` 面向接手者讲项目是什么、如何开始以及去哪里找权威资料。
- `docs/index.md` 是人类可读的资料总入口，不依赖某次聊天或某个 AI 的记忆。

## 3. 每类资料放哪、谁维护、何时更新

角色可由同一人承担；没有任命时写“待指定”，不能杜撰责任人。

| 资料与位置 | 最少内容 | 负责角色 | 更新触发 |
|---|---|---|---|
| `AGENTS.md` | 执行边界、验证入口、事实文档链接 | 项目维护者 | 规则或入口获准变更 |
| `README.md` | 项目用途、启动路径、支持范围 | 项目维护者 | 使用与接入方式变化 |
| `docs/index.md` | 分类、真实路径、状态、负责人 | 文档维护者 | 新增、替代、移动或归档 |
| `docs/project/` | 简报、目标、范围、里程碑、风险与决策 | 项目负责人 | 范围、计划或承诺变化 |
| `docs/project/status.md` | 当前平台/档位/目标、门与产物证据索引 | 当前接手人 | 基线、门、产物或授权范围变化 |
| `docs/research/` | 证据来源、日期、假设、验证结论 | 研究负责人 | 获得新证据或旧结论过期 |
| `docs/product/` | 需求 ID、用户任务、业务规则、验收标准 | 产品负责人 | 规则或需求获准变化 |
| `docs/design/design-system/` | token、组件规范、交互与文案约定 | 设计与前端负责人 | 共享模式变化 |
| `docs/design/prototypes/` | 原件、快照、反馈与批准记录 | 设计或功能负责人 | 每次评审与实现对照 |
| `docs/architecture/` | 系统边界、模块、依赖、部署视图 | 技术负责人 | 边界、调用关系或依赖变化 |
| `docs/architecture/decisions/` | ADR：背景、选项、取舍与后果 | 决策负责人 | 重要决策及其被替代时 |
| `docs/data/` | 数据字典导航、归属、生命周期与兼容策略 | 数据负责人 | 模型、保留或迁移策略变化 |
| `docs/api/` | API 权威定义入口、认证、版本与示例 | API 负责人 | 合约或兼容性变化 |
| `docs/security/` | 权限、信任边界、威胁与隐私处理 | 安全责任人 | 数据、角色、集成或风险变化 |
| `docs/testing/` | 验证矩阵、命令、环境与实际结果索引 | 测试与开发负责人 | 验收条件或验证方式变化 |
| `docs/operations/` | 环境、发布、迁移、恢复和故障操作 | 运维或服务负责人 | 拓扑、发布、故障和演练变化 |
| `docs/releases/` | 版本、制品、差异、影响、验收与回退 | 发布负责人 | 每次发布或撤回 |
| `docs/ai/handoff.md` | 当前基线、事实、未完成项与下一步 | 当前接手人 | 会话交接或阶段结束 |

## 4. 唯一真相与最小维护规则

- 技能包以 GitHub 仓库为唯一源码，it-note 只做导航摘要，流程见 [同步与版本](sync-and-versioning.md)；此约定不自动替其他项目指定仓库或增加远程授权。
- schema、API 定义、迁移代码以项目指定的可执行或生成源为唯一真相。
- 文档链接权威源码并解释业务含义；生成文档注明生成命令和来源，不再人工维护冲突副本。
- 配置示例只放变量名、格式和安全占位值；真实密钥放项目认可的秘密管理位置。
- 文档分清教程、操作指南、参考与解释；小项目可同页分节，不强制四套文档。
- 行为变化时同一任务更新对应文档，不能仅在聊天里解释新规则。
- 文档暂时无法同步时记录差异、适用版本与待办；不把旧文档标成最新事实。
- 历史报告仅证明其记录版本；不能替代当前源码与环境的实际核对。
- 失效内容保留历史或替代链接，避免删除唯一决策与批准证据。
- 不额外复制整套第三方文档；记录官方入口、使用版本和项目自己的约束。

## 5. 环境与权限：`operations/environments.md`

- 列出本地、开发、测试、预发布、生产等实际存在的环境，不臆造环境名称。
- 画清服务、数据库、存储、队列、第三方接口、网络边界和关键依赖。
- 每个环境写用途、负责人、访问入口、部署方式、数据来源和与生产的差异。
- 记录权限申请与撤销流程、角色边界、最小权限和紧急访问的审批入口。
- 操作入口可以指向受控控制台；不写密码、私钥、令牌或可直接冒用的会话链接。
- 列出域名、DNS、TLS 证书、签名证书、云资源和外部服务的责任归属。
- 记录到期日或账单周期、续费方式、提醒接收人及停用风险，不假定自动续费可靠。
- 配置项记录用途、必填性、默认值风险、环境差异、变更与重启要求。

## 6. 部署与业务验收：`operations/deployment.md`

- 写明授权前提、执行角色、目标环境、变更窗口、锁和停止条件。
- 识别不可变制品：版本、提交、构建编号、镜像 digest 或包哈希及其来源。
- 记录依赖、配置版本、签名或完整性检查；禁止靠 `latest` 推断实际部署内容。
- 发布前列出备份、兼容性、容量、迁移与回退条件，链接对应文档。
- 发布步骤记录预检查、灰度或批次、状态核对、流量切换及完成条件。
- 区分进程存在、健康检查、依赖就绪和关键业务流程成功，分别提供验证办法。
- 业务冒烟用获准的测试账号和合成数据，明确是否触发通知、费用或真实外部写入。
- 每次执行留目标、时间、操作者、制品身份、检查输出和未验证项，不记录密钥。
- 命令超时或连接中断先核对实际状态，不能因结果不明重复部署或重复写数据。
- 桌面或移动应用适用时，增加签名、公证、安装路径、权限、升级与数据保留检查。
- 只做文档准备不代表允许真正发布；执行授权与生产约束仍按当前项目规则处理。

## 7. 数据变更：`operations/migrations.md`

- 对每次迁移写需求 ID、权威脚本、执行顺序、预计耗时、锁表和容量影响。
- 标出应用新旧版本与 schema 的兼容关系，以及滚动部署时的混跑窗口。
- 优先评估“扩展 → 回填 → 切换 → 收缩”，破坏性删除与代码切换分开安排。
- 写清回填范围、批量大小、断点、幂等条件和完成后的一致性核对办法。
- 执行前确认备份与恢复可用，评估索引、长事务、复制延迟和读写阻塞。
- 迁移失败或结果不明时先查已执行步骤、版本表和数据状态，再决定继续或停止。
- 标记不可逆操作、数据丢失风险和所需授权；不能假设每个迁移都有安全 down 脚本。
- 不把数据库迁移文档当成可执行迁移脚本的替代品，也不自动运行其中的命令。

## 8. 回滚与前滚：`operations/rollback.md`

- 按制品、配置、数据库、外部副作用分别说明可以撤回什么、不能撤回什么。
- 触发条件写成可观测信号，并指定决策人、最长等待窗口与通知对象。
- 保留可定位的旧制品、旧配置与兼容证据，不能只写“重新部署上一版”。
- 回退应用前检查旧代码能否读取新数据；恢复数据库前评估新增交易和写入丢失。
- 破坏性 schema 或外部已生效动作可能更适合前滚修复；记录选择依据。
- 写明切流、停写、验证、重放或对账步骤及失败后的升级路径。
- 回滚完成也要做健康与业务验证，记录实际状态，不把命令返回成功当作恢复成功。

## 9. 备份恢复：`operations/backup-restore.md`

- 盘点数据库、上传文件、对象存储、必要配置与加密依赖，说明一致性边界。
- 按业务定义 RPO（允许丢多少数据）与 RTO（允许恢复多久），没有承诺时标待确认。
- 记录备份频率、保留周期、加密、隔离、访问权限、存放位置和失败告警。
- 数据库与文件需按可恢复的一致点关联；只备份一边可能无法恢复完整业务。
- 明确恢复目标、前置资源、恢复顺序、完整性与业务一致性检查。
- 在隔离且获准的环境做恢复演练，记录备份身份、耗时、实际数据缺口和失败项。
- “备份任务成功”不等于“可恢复”；没有恢复演练就明确标 `unverified`。
- 演练不得覆盖生产或泄露真实数据；需要真实数据时另行确认访问、脱敏与清理要求。

## 10. 监控、故障与生命周期：`operations/runbooks/`

- 每个实际高风险故障有可检索入口：症状、影响、告警、初步诊断和止损条件。
- 指定服务负责人、当班或升级路径；联系人不可用时给备用角色或组织入口。
- 日志、指标和追踪至少能定位关键请求与依赖失败；避免采集密钥和无关个人内容。
- 告警记录阈值或异常定义、持续时间、路由、静默与解除条件，不只写“接入监控”。
- runbook 写安全只读检查、允许的恢复动作、所需授权、验证和无法恢复时的升级路径。
- 高风险命令写目标确认与停止条件；示例不直接嵌生产地址和凭证。
- 故障后补时间线、实际处置、根因证据、影响范围与后续任务，修正无效步骤。
- 升级运维说明增加版本兼容、依赖弃用、维护窗口和用户通知，适用时检查签名到期。
- 停服分支说明数据导出格式、身份核验、截止时间、保留与删除、域名和资源解约。
- 停服、删除、导出他人数据或取消付费资源必须有相应授权；写计划不代表允许执行。

## 11. 证据存放、保留与敏感隔离

- 小型文本、可编辑源码和可安全公开的少量截图可随代码版本管理。
- 大型视频、完整构建包、密集截图和原始日志优先进入受控制品库，不直接塞进普通 Git。
- Git LFS 仅在项目已配置、权限与配额合适时使用，不能默认安装或启用。
- Git 中保留证据索引：相对路径或受控 URI、版本、日期、生成方式、大小及哈希。
- 哈希用于核对制品身份，不替代访问控制、签名验证和内容真实性审查。
- 指定保留周期、删除责任人、访问范围与链接有效期；临时下载链接不作唯一索引。
- 敏感日志、客户数据、原始访谈和凭证材料隔离保存；文档只链接获准的脱敏摘要。
- 提交前检查秘密、个人数据、绝对个人路径和敏感截图；误入 Git 后不能只靠删除当前文件消除历史。
- 不擅自公开文档站、对象桶、预览端口或第三方上传；先核对授权与资料分级。

## 12. 状态、门与交接

- 文档生命周期使用 `draft / approved / implemented / superseded`，附适用版本和替代关系。
- `approved` 需真实批准人、日期、范围和证据；`implemented` 关联实际实现与验证，不伪造。
- 检查结果统一用 `pass / na / unverified / blocked`；G0..G6 的阶段定义只看主 `SKILL.md`。
- 缺环境、缺权限或缺工具时记清哪一项未验证或被阻塞，不把整套运维准备概括成通过。
- 交接记录当前基线、事实、授权边界、已完成、待办、风险、验证证据和下一步；不记录密钥。
- 提交交付前检查文档差异、相对路径、引用、事实版本与重复规则，不运行无关业务构建。
- 本篇模板入口：[项目简报](../assets/templates/project-brief.md)、[ADR](../assets/templates/architecture-decision.md)。
- 操作与收尾模板：[runbook](../assets/templates/operations-runbook.md)、[就绪检查](../assets/templates/startup-readiness.md)、[AI 交接](../assets/templates/ai-handoff.md)。

## 13. 最小状态索引

新项目默认用 `docs/project/status.md`，已有项目映射到现有 issue/状态页；这只是文档索引，不是新造业务 schema、数据库或管理平台。
其他页面引用此处字段，不各维护一份当前状态。可同页合并，只有实际内容才创建。

| 字段 | 最少记录 |
| --- | --- |
| `baseline` | 仓库、分支、固定 commit/tag；未提交差异另记摘要，不能假装已有提交 |
| `profile` | 平台、档位及风险依据、交付目标，三者分开 |
| `authorization` | 当前允许/禁止的副作用及可追溯依据 |
| `updated_at` | 本次事实核对日期，不用编辑时间冒充验证时间 |
| `gates[]` | 门 ID、`pass/na/unverified/blocked`、证据/理由、验证日期、下一步与负责人 |
| `artifacts[]` | 路径/受控 URI、版本、`draft/approved/implemented/superseded`、来源/批准证据 |
| `next` | 当前阻塞、未验证影响、下一步与前提 |

示例（非真实项目验收）：

```text
baseline: local draft; branch/commit not created
profile: CLI; standard; startup-ready
  reason: ordinary new tool, no high-risk trigger found
  authorization: local draft only; no install or remote write
updated_at: YYYY-MM-DD
gates:
  - G2 | unverified | source/contract.html | browser check pending | owner: TBD
artifacts:
  - source/contract.html | v1 | draft | local draft, no approval claimed
next: render narrow/wide viewports before claiming G2 pass
```

字段名和 ASCII 示例为便于对齐，真实说明可用中文；空白责任人必须标待指定，不伪造决定。
同步状态不塞入业务门当作功能通过证据，另按 [同步记录](sync-and-versioning.md) 记两端版本、回读与落后状态。
