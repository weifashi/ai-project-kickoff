# 源码、笔记导航与版本同步

本篇只定义来源、同步与核验方式，不授予创建仓库、推送、公开、安装或跨机器同步的权限。
默认项目目录与状态字段分别见 [资料地图](documentation-and-operations.md#2-默认资料地图) 和 [最小状态索引](documentation-and-operations.md#13-最小状态索引)。

## 1. 唯一源码，不双向改正文

- **GitHub 仓库是本技能包唯一源码**：入口、参考、模板、测试及项目内 HTML 原件随版本追踪；本地工作树是待同步副本，不谎称已上线。
- **it-note 只做导航摘要**：记录用途、当前状态、固定版本入口、验证日期、限制和下一步；不再复制维护另一套完整技能正文。
- 笔记发现错误时回到源码修改并验证，再更新摘要；不从较新笔记时间推断它比仓库更权威。
- 本包制作时的历史同步授权记录在仓库设计说明；它不增加当前任务权限。实际仓库、可见性和笔记节点以当前任务确认的对象为准，不能推广为未来任一项目、仓库或其他设备的默认授权。
- 公开可见性、创建/写远程、安装到本机或其他设备各自核对授权；有源码同步授权不等于有安装或公开内部材料的授权。
- 本轮保持 `draft`、暂不安装；同步成功也不能改写为“技能已生效”。不修改当前机器的全局 skills。

## 2. 链接必须固定版本

摘要和交付记录至少包含：

```text
source: <confirmed GitHub repository>
revision: <full commit SHA or immutable release tag>
entry: <permalink to SKILL.md at that revision>
status: draft | approved | implemented | superseded
verified_at: YYYY-MM-DD
verification: <actual checks and evidence link>
note: <confirmed project/node ID or controlled URL>
sync: source=<state>; note=<state>; checked_at=<date>
```

- `main`、`develop` 等可移动分支链接可作便利入口，但不能代替固定 commit/tag 的版本证据。
- tag 若允许移动，还应记录解析后的完整 commit SHA；不能只凭 tag 名称核对内容。
- 日期说明验证哪份源码、哪些检查；仅打开链接或更新时间戳不能算全部验证通过。
- 尚未提交时写“本地草案，commit 未创建”，保留本地差异证据；不能填造 SHA、tag 或远程链接。
- HTML 预览只指向归档版本的展示副本；`preview_html`、8008、`~/www` 或临时截图都不是唯一源码。
- 密钥、真实账号凭证、个人内容与不获准外传的截图不进入仓库或笔记摘要；大型证据用受控索引，不把临时下载链接当唯一档案。

## 3. 一端一端写，写后回读

1. 核对授权、对象、当前远端版本与本地差异；已有变更先保留，不覆盖不属于本次任务的内容。
2. 本地完成受影响检查，保留实际输出；只同步已核对的源码版本。提交/推送等动作仍须当前授权覆盖。
3. GitHub 写入后回读仓库与文件，核对目标分支、完整 commit、关键路径及内容；超时/未知不能直接再推一次。
4. 取得固定版本后，再将该版本、验证日期和简明变化写入已确认的 it-note 节点。
5. 笔记写后回读节点，核对 ID、标题、固定版本链接、状态和日期，不能仅凭工具“成功”判断摘要正确。
6. 两端都核对后记录各自实际版本与同步状态；没有安装授权就到此为止。

## 4. 部分失败与失效记录

- 写操作超时或连接中断先查实际状态，避免重复建仓库/节点、重复追加或覆盖他人改动。
- GitHub 成功但笔记失败：保留已核验源码，记录“笔记落后于 `<commit>`”、失败原因和安全补同步步骤；不回滚正确源码掩盖摘要故障。
- 源码未成功：笔记不能声称该版本已存在；可保留已确认的上一版本并注明新草案未同步。
- 工具、权限或远程不可用：保留本地草案、最后成功版本/核验日期和具体限制，状态记未同步/落后；不把缓存说成最新。
- 有界重试仅用于已确认安全的瞬态错误；结果不明或对象冲突时先停止写入并调查。
- 内容改变后重跑受影响验证并更新固定版本；历史通过结果只证明历史版本，摘要不冒充当前证据。

同步状态是来源管理记录，不替代 G0–G6 门状态或产物批准。最终汇报分开说清：本地已完成、远端已核验、笔记已回读、尚未安装和未验证项。
