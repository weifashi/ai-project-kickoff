# 单页 HTML：需求方案 / 实际改动

本技能是 ai-project-kickoff 专用配套，不替换机器原有 html-mockup；其他项目的通用HTML任务仍沿用其当前技能选择。

一页 HTML 讲清一件事：先说人话，再画页面、规则、流转。不要用技术名词列表代替业务解释。

## 先选模式

| 模式 | 何时用 | 必须交付 |
|---|---|---|
| A 方案原型 | 要做成什么样、效果图、需求评审、方案对比 | **固定输出 HTML**，标“方案 / 未实施” |
| B 实际改动 | 总结全部改动、表字段、原有规则、影响与回滚 | **固定输出 HTML**，以最终真实差异为底账 |

按任务范围调节篇幅，不能因为“改动很小”免掉 A/B 的 HTML。
主流程有轻量 / 标准 / 高风险档时沿用其档位，不另建报告分级。
要真实交互、对齐生产组件或编译进应用时，使用项目原有前端流程；说明性 HTML 不冒充可用产品。

## 权限与归档

- **长期唯一归档在当前项目** `docs/design/prototypes/<slug>/source/index.html`，遵守项目忽略与提交策略；生成文件不等于获准提交。
- 默认记录放 `docs/design/prototypes/<slug>/index.md`，素材/证据使用同级 `source/`、`snapshots/`、`reviews/`；项目已有布局时保留实际映射，不另开孤立目录。
- 同一事项复用目录，改版记录日期/版本和更新锚点；不无故丢弃旧链接。
- `preview_html`（仅当客户端实际提供）和已有服务器都只展示归档的**副本**；展示失败不丢失源文件。
- 默认交付项目路径。有工具则可附内联预览；没有就明确工具不可用，不编造链接或已预览。
- **不自动**起服务器、监听公网、修改端口分享、上传文件、安装依赖、改全局规则或安装技能。
- 用户明确授权发布时，才沿用其指定通道并检查实际可达；无法证实第三方可访问，不宣称公开可用。
- 不捆绑机器域名、业务帐号、令牌、私人绝对路径；展示用合成数据，真实隐私截图需另有授权。

## 共同视觉与内容规则

1. 从 [assets/template.html](assets/template.html) 复制起手，不抄旧页面过时 CSS。
2. **自包含单文件、无 CDN**：CSS 内联、系统字体、图标用文字/Unicode、图片用内联数据、图用内联 SVG。不加载外部字体/脚本/图片。普通引用链接是导航，不是资源加载。
3. **正文至少 16px**，说明也保持可读；不要缩字来塞内容。界面静态展示，不伪造能执行真实业务的按钮。
4. A 用 `.wrap`（900px）；完整后台可 `.wrap.desk`（1180px）；**B 页头、导航、正文一律 `.wrap.rep`**，宽度随屏幕增长，上限 1920px。
5. 报告长文字收在 `52em`；宽表、图、对照使用可横滚容器；`.rep .bleed` 不向外挣脱。手机双栏改单栏，不能让整页横向滚动。
6. 现状灰白；本次新增/修改绿色；主操作琥珀；警告/删除红色。只给真正 Mermaid 图用黑底，其他页面浅色。
7. ASCII 结构/文件清单放 `<pre class="ascii">`，只用半角 `+--`、`` `-- ``、`|`、`->` 和空格对齐。中文放框外说明，不参与列宽。
8. 每条规则都写 **页面 → 操作 → 改前结果 / 改后结果**，并画出实际页面帧。解释放 `.hint`，不冒充 UI 文案。
9. 状态机、调用链必须是**真正显示的图**，不能只贴 Mermaid 源码。小图可直接写内联 SVG；复杂图使用 [assets/blocks.html](assets/blocks.html) 的 Mermaid 卡和渲染器。
10. 先查真实代码/截图/issue，再画现有界面与字段；用项目真实术语。未核实就标待确认，不能凭印象补业务事实。

## 模式 A：需求方案

1. 查现有归档与需求证据，复用目录；说明本版边界、假设、未决事项。
2. 页头：功能名 + 一句话目标 + 日期 + “方案未实施”。
3. 超过 3 个界面加锚点导航；第二版起加绿色“本次更新”并链接到变化处。
4. 一节一件事：入口/何时出现 → 页面帧 → 操作 → 结果；规则与异常分支写旁边。
5. 用对照、字段表、矩阵或流转图表达，不为凑图堆页面；说明权限/数据/兼容性影响与验证计划。
6. **方案不是实际改动**：不要写已上线、验证通过或实际上未改的表字段。

## 模式 B：实际改动

执行前阅读 [references/change-report.md](references/change-report.md)。铁律：

- 明确本次基线与最终源码范围；逐行读完整 diff，不只读 `--stat` 或代理摘要。
- 以文件底账对照 S1 ASCII 树，覆盖**全部文件集合**，不是只核对数量；包括新文件、删除、重命名、配置、测试、生成物。
- 每处差异归到“规则变化 / 无规则影响 / 待确认”之一；保留真实位置。纯重构不能编造成规则变化。
- 如工具和权限允许，把独立证据采集并行分派；代理不足则分批或单线程完成并如实说明，不伪称六代理同时执行。主线程复核冲突与关键风险。
- 必有：表字段、原规则 → 新规则 → 触发条件 → 影响方、业务点、接口/文案、风险、代码/数据回滚与验证证据；无变化明确写“无”。
- 页面必须画出来。无直接页面的后台任务画真实任务/接口入口，并说明用户如何感知；性能/重构也说明同一操作结果是否变化。

固定 S0-S7 骨架：一句话结论 / 改动全景 / 表字段 / 规则与页面 / 流转调用链 / 影响矩阵 / 接口文案 / 风险回滚验证。
篇幅可短，证据闭环不可删。

## 渲染与实际检查

下面 `<skill-dir>` 是本技能目录，`<page>` 是项目归档文件；先替换占位符。
配套不安装依赖、不启动 HTTP 服务；检查只对**受控本地 HTML**，不登录个人帐号、不访问业务 API。

```bash
# 仅有 Mermaid 卡时执行；原生内联 SVG 不需要此步
python3 <skill-dir>/assets/render-mermaid.py <page>
# 真实 Chrome/Chromium + Node >=22（内置 WebSocket）；每个请求视口都必须实际测到
python3 <skill-dir>/assets/check-overflow.py <page> --widths=390,768,1440
# 可选：授权写入本地截图目录后，生成实际浏览器截图供人工检查
python3 <skill-dir>/assets/check-overflow.py <page> --screenshots=<local-evidence-dir>
```

- Mermaid 需要**已有** `mmdc` 及可启动的 Chrome；缺少时返回非零并保持文件不变，报告“图未渲染”。可改用真正的手写内联 SVG，不可保留源码假称完成。
- 卡片格式固定 `<figure class="mmd" data-mermaid><pre>转义后的源码</pre></figure>`；渲染后保留折叠源码，宽图只在图容器横滚。源码修改后用 `--force`。
- `CHROME_PATH` 可显式指定浏览器。默认保留 Chrome 沙箱；仅在可信隔离容器且确实无法启动时，检查可显式 `--no-sandbox`，渲染可显式设 `HTML_MOCKUP_NO_SANDBOX=1`，并在证据中披露。
- 溢出工具通过 CDP 设置布局视口；**请求 390 而实际 485 不算验收**。空探测、超时、缺文件、浏览器失败、宽度不符均非零，不能用后续成功覆盖。
- 实际打开/截图检查页面文字、字体、图、布局、颜色与对照；命令通过不能替代人工视觉检查。检查全部图已显示、源码可折叠，不数全页 `<svg>` 冒充逐卡验证。
- 若浏览器、渲染器或预览工具缺失：仍归档 HTML，清楚标“未验证 / 未渲染”与原因；不说完成视觉验收，不自行安装。
- 内容变化后重跑受影响检查；检查通过只证明对应文件/视口/时间，不证明业务正确。
