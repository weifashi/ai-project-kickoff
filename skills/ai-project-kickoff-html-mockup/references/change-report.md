# 模式 B：实际改动报告

## 1. 先确定真正底账

先确认仓库、分支、已有改动、项目规则，以及用户指明的比较范围。
不要默认 `origin/develop` 存在，不自动 fetch、不替用户选一条看起来方便的基线。
记录基线 SHA、最终 HEAD、工作树/暂存区/未跟踪文件是否纳入。

```bash
git status --short
git branch --show-current
git rev-parse HEAD
# <base> 必须先核实；以下是命令形式示意，不应原样执行
# 提交范围：git diff --name-status -z <base> HEAD
# 文件行数：git diff --numstat -z <base> HEAD
# 完整内容：git diff <base> HEAD -- <path>
# 未提交：git diff HEAD -- <path>；新文件需直接逐行读取
```

- 提交与未提交若都在范围，分别留证后合并**路径集合**，不能双算同一文件。
- 用 NUL 分隔获取路径，保留有空格/非 ASCII 的真实路径；不要用扩展名正则计数，防止漏无扩展名文件与误计正文例子。
- 重命名记录旧/新路径；删除记录旧内容证据；二进制或生成物写明不能逐行比较的原因、生成来源和验证方式。
- 逐行追到调用方/默认值/异常路径；新增与删除行都要有归类。`file:line` 对应哪一侧源码必须说清。
- 输出一个可复核文件台账（可在 HTML 中用 `data-file`、表格或嵌入 JSON），使“底账集合 == 报告覆盖集合”，不是碰巧数量相同。
- 不需要为了报告提交、推送、部署或修改业务代码。

## 2. 并行采集，不丢主线程责任

独立调查线可分派；有多少代理槽就并行多少，剩余分批，不虚报并行数量。
每个任务明确 **相同基线、实际完整文件清单、必须读取完整 diff、不准只读 --stat**。
不能发给代理尚未存在的另一代理结果，必须先提供文件台账或拆成可独立调查的范围。

| 线 | 证据输出 |
|---|---|
| 清点 | 文件、增删/重命名、±行数、业务一句话、是否触规则 |
| 数据 | 表字段、索引、默认/可空、存量处理、兼容性、DDL锁、回滚 |
| 规则逐行 | 原/新判断、阈值、金额、状态、权限、排序、时间窗、幂等、异常分支 |
| 调用与影响 | 改动符号全部相关调用方、端、角色、触发路径 |
| 契约与文案 | 请求/响应/错误码、老客户端、真实 locale 与缺 key；不要套别的项目语种数量 |
| 验证风险 | 最终源码测试证据、事务/并发/超时、上线顺序、代码/数据回滚 |

每条发现给位置与置信度；不确定标待确认。
主线程看原始证据复核冲突，不把两种矛盾解释揉在一起；被证伪的重点疑点可以列“已排除及原因”。
代理口头“测试通过”不能代替主线程看到最终命令与结果。

## 3. 固定八节，先人话后证据

模式 B 页头、导航、正文统一 `.wrap.rep`；需要长表就让表自身横滚。

| 节 | 内容 |
|---|---|
| S0 一句话 | 改了什么、为什么、用户能感到什么；基线和实际完成状态 |
| S1 全景 | ASCII 全文件树 + ±行数 + 规则ID或“无规则影响”，与台账集合对齐 |
| S2 表字段 | 表/字段旧新定义、索引、可空/默认、存量、兼容、锁、回滚；没有就明确无 |
| S3 规则与页面 | 原规则→新规则→触发条件→页面→操作→改前/后结果→受影响方→代码位置→风险 |
| S4 流转调用 | 真正渲染的状态图/请求链；未变也可画现行路径解释触发条件 |
| S5 业务影响 | 端 × 角色 × 场景 × 调用方；谁无变化也说清 |
| S6 接口文案 | 路由、字段、状态码、breaking、老客户端、locale；没有就明确无 |
| S7 回滚验证 | 代码/数据分开；可逆性、备份/恢复前提、已运行命令/结果/证据、跳过/未验证 |

每个 S3 规则卡下面都画页面（手机帧、后台壳、列表、前后对照），不是只写页面名。
纯性能/重构：相同页面与操作、输出是否一致、性能证据；不要一句“用户无感知”跳过。
纯后台无页面：画任务/API入口与上下游可见结果，写为何没有直接页面。
回滚 SQL 只是经核对的说明，不自动执行；删字段/不可逆迁移不可假称能直接回滚。

## 4. 收尾证据

- 全部文件集合一致；每个差异已归类“规则 / 无规则影响 / 待确认”。
- 四块齐：表字段、原有规则变化、业务点、回滚。
- 每张规则卡有真实旧/新引用、触发条件、操作、结果和画出的入口。
- 每张 Mermaid 真的有内联图；不能拿普通 SVG 图标凑数量。
- 最终 HTML 用真实浏览器检查 390/768/1440，记录请求/实际宽度；人工看截图确认可读。
- 未渲染、未测、uncertain 仍存在时明确列出，不能包装成全部完成。
- 归档项目路径；展示副本失败不影响归档；发布需额外授权。
