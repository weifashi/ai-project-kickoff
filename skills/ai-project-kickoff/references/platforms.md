# 平台与风险裁剪：共用质量门，不统一技术栈

先选一个主平台；混合项目可以组合，但只为本次范围启用必要模块。
再叠加 LLM、离线/外设、交易和敏感数据等风险；本表不是所有行业的合规清单。
G0–G6 定义与门状态只看 [主入口](../SKILL.md)；阶段证据见 [生命周期](lifecycle.md)。默认产物位置以 [文档与运维](documentation-and-operations.md) 为唯一来源。
默认沿用团队现有能力、项目技术栈和运行平台，不永久绑定 Next.js、shadcn、Supabase 或任何供应商。

## 一、三项独立记录，再做裁剪

- **平台**：产品在哪里运行，例如桌面、Web、CLI；不是流程档位。
- **档位**：轻量 / 标准 / 高风险，**默认标准**；决定证据深度，不决定要不要数据库。
- **交付目标**：探索/方案、开工就绪、最小真实切片、获准交付上线；决定本轮停在哪里，不自动授权安装或部署。

| 档位 | 适用条件 | 保留的最小证据 |
| --- | --- | --- |
| 轻量 | 边界已知、影响小、可逆，且无下述高风险触发项 | 一页范围/验收、方案 HTML、最小契约与实际受影响检查；文件可合并 |
| 标准 | 一般新项目、跨模块功能或不确定性尚未厘清 | 完整主流程及失败状态、关键决策/数据契约、真实切片与回归、交接索引 |
| 高风险 | 资金、敏感数据、高影响权限/跨租户边界、不可逆动作或其他高影响风险 | 标准证据加对应风险 spike、负向/并发/恢复验证、明确审批与审计、可核验恢复责任 |

各平台和风险**叠加后取最高档**，不取平均；未知影响先保持标准并调查，疑似高影响项查清前按高风险隔离。
资金、敏感数据、权限、不可逆操作不能因“小工具”“只改一行”或赶时间降档。
合法降档必须先消除触发风险并留下事实依据；时间压力只能缩范围，不能改变风险事实。
三档都必须使用 html-mockup 讲方案/报告并如实记录证据，不等于每档都造完整后台。

### 裁剪步骤

1. 确认交付物：内容、Web、移动包、桌面包、API/CLI/SDK，还是已有项目的有限改动。
2. 先问目标任务与运行环境，不先问“用哪个框架”；已有可信决定直接沿用并注明依据。
3. 标记是否需要 UI、身份/权限、持久化、多端同步、计费、外部系统与在线运行。
4. 选择最小必要能力：允许无 UI、无登录、无数据库、无服务端、无云、无实时同步。
5. 默认标准，按风险叠加取最高档，再选必要验证；标记采用、只建议、未验证项，不把可选项当必做范围。
6. 为被删减的重步骤记录理由；必需能力未验证用 `unverified`，不是 `na`。
7. 列真设备、真实服务、费用、权限和数据的访问限制；本地开发授权不自动包含这些操作。
8. 用最小真实切片验证路线；一旦平台事实推翻方案，回到受影响门而非坚持原选型。

## 二、主平台裁剪矩阵

G0/G1 各平台都需要明确上下文、授权、问题、范围和验收；深度随任务缩放。
G2 不强制业务 UI：没有界面时，用契约、调用样例和流程 HTML 作为体验产物；html-mockup 不记 `na`。
G3 不强制数据库：边界、数据流与可验证实现方案仍需说明。

| 主平台 | G2：体验/契约 | G3：实现与关键风险 | G4：真实切片 | G5/G6：制品与交付重点 |
| --- | --- | --- | --- | --- |
| 官网/内容站 | 站点地图、内容层级、核心阅读/转化路径 | 内容来源、渲染/托管、搜索和表单是否真的需要 | 真实内容经构建到目标浏览器；如有表单验证实际结果 | 链接/资源/响应式/可访问性；发布与内容维护责任 |
| Web/SaaS/后台 | 任务流程、信息架构、状态与适用的角色权限 | 业务状态、接口/数据、边界与隔离；按需登录/数据库 | 一个完整任务贯通真实接口与必要存储 | 生产模式制品、权限回归、配置/迁移与恢复 |
| 移动应用 | 设备尺寸、平台导航、返回/中断/权限流程 | 生命周期、网络/电量、存储与平台能力 | 目标设备/模拟器完成核心流程；真机限制单列 | 包身份/签名、安装升级、前后台与分发授权 |
| 桌面应用 | 窗口、菜单、快捷键、系统权限及适用的托盘 | 进程边界、本地文件/凭据、平台集成与更新 | 实际应用入口到结果；OS 相关能力不能只用内部桩验证 | 目标系统安装包、签名/公证等适用项、升级与回滚 |
| API | 请求/响应、错误、身份与版本契约 | 协议、并发/重试、兼容性、数据与外部依赖 | 实际调用到真实结果；写操作验证重复/失败边界 | 可部署制品、契约测试、文档、健康与运维责任 |
| CLI | 命令/参数、stdin/stdout/stderr、退出码与示例 | 文件/环境/权限边界、非交互运行、依赖分发 | 实际命令处理合成输入并产生约定输出 | 目标平台可执行物/包、安装卸载、错误与脚本兼容 |
| SDK/库 | 公共 API、类型、调用/异常示例 | 语言/运行时兼容、依赖、版本策略与安全边界 | 独立消费者安装并执行最小实际用例 | 发布包内容、类型/导入路径、文档、兼容与升级说明 |
| 已有项目 | 现有行为 → 本次变化 → 用户影响 | 保持现有架构与兼容，核对真实调用和数据 | 改动路径真实通过，同时保护相邻旧行为 | 最终改动与回归证据、迁移/发布差异、交接更新 |

## 三、官网与内容站

- 内容本身是产品输入：谁提供、是否有使用权、谁审核和更新，不能用 AI 编造事实填空。
- 无账户/无动态数据时优先评估简单静态交付，不为“完整产品”额外创建后台与数据库。
- 表单、搜索、订阅、统计、支付等逐项确认；只有视觉按钮不代表功能已经交付。
- 如目标涉及搜索发现，再定义适用的页面标题、可索引性、链接和内容结构验收。
- 内容更新频繁或多人协作时再评估 CMS；团队不能维护的 CMS 不是默认更好。
- 验证真实素材、失效链接、不同屏宽、键盘与可读性；不能只看一张桌面截图。
- G6 说明域名/托管/证书的实际责任和授权，不擅自购域名或开收费服务。

## 四、Web / SaaS / 业务后台

- 根据任务复杂度组织导航，不先复制“仪表盘 + 左菜单 + 用户管理”的壳。
- 身份验证与业务授权分开：是否需要账户、哪些操作需要谁的权限，分别确认。
- 多租户是明确需求时才启用；一旦启用，验证跨租户读取、写入、导出及后台任务隔离。
- 数据模型跟着业务状态与生命周期走，不把页面字段直接等同于数据库表结构。
- 核对浏览器兼容、失败反馈、并发编辑与长任务；只对实际需求增加实时能力。
- 有列表/筛选/导出时验证空、分页、大数据和权限边界；不要默认一次取全数据。
- 有迁移时记录旧新版本兼容窗口、字段默认值和回填/恢复策略；实际迁移另按授权。
- 后台不是自动低风险：删除、批量操作、权限和财务操作需按真实影响加确认与审计。

## 五、移动应用

- 明确目标 OS/最低版本、原生/跨平台现有能力、分发渠道与可用测试设备。
- 尊重平台导航、系统返回、手势和安全区域；不直接把桌面页面缩窄当移动设计。
- 列冷启动、后台/恢复、系统终止、网络切换、权限拒绝和升级后的核心行为。
- 推送、定位、摄像头、相册、蓝牙等仅按需求启用；先说明用途，再按平台流程请求。
- 真机能力与模拟器能力分开记录；没有真机时不能声称外设、耗电或真实权限已验证。
- 安装包核对标识、版本、签名和目标平台；商店提交/账号操作不由构建成功自动授权。
- 如需离线/同步，叠加第十节；如只读在线内容，仍定义断网反馈而非默认离线数据库。

## 六、桌面应用

- 明确目标 OS/芯片、最小版本、分发/更新方式，以及是否依赖系统授权。
- 优先延续现有平台能力；选原生、Electron、Tauri 或其他方案需写团队维护与包体/集成取舍。
- 识别窗口/后台进程/系统扩展边界；窗口存在不等于热键、选区、截图等系统能力可用。
- 本地文件、系统凭据和个人内容只在本次授权范围访问，验证优先用受控窗口与合成文字。
- 不自动授予辅助功能/屏幕录制权限，不重置权限数据库、不关闭系统安全防护。
- 按需验证正常退出、未保存内容提示、重复实例、设置/历史保留和升级兼容。
- 对实际安装制品验证身份、启动和关键交互；代码签名通过不能代替业务验收。
- 安装替换/重启会影响用户会话，需有明确授权及可回滚旧包；结果不明先核对版本与进程。

## 七、API / CLI / SDK：无 UI 不是无体验

- API 示例覆盖成功、无效输入、权限不足和适用的分页/限流；错误结构需可供调用者处理。
- CLI 定义人读与机器读输出、错误通道、退出码、非交互行为及破坏性操作保护。
- SDK 明确最低运行时、公共导出、同步/异步、资源释放和异常契约；不以仓库内导入代替包验证。
- 无登录的本地转换工具仍需要文件访问边界；公开只读 API 也需按实际风险评估滥用和成本。
- “无数据库”可采用文件、内存或外部系统，也可以无状态；写明数据生命周期即可。
- G2 用契约/调用示例做流程 HTML，不能记成“没有 UI，所以体验门或 html-mockup 不存在”。
- G4 验证真实消费者路径：请求、命令或外部示例工程；不能仅调用内部私有方法。
- G5 测实际打包产物与安装/导入；G6 交付用法、版本兼容、诊断与维护边界。

## 八、已有项目：先理解，再最小改动

- 先核对仓库/分支、用户未提交改动、任务路径规则、运行入口与已有验收方式。
- 从现有页面/接口追到业务规则、数据与调用者，不只改用户截图里能看到的一层。
- 复用当前团队能力和组件；新需求不等于有权更换框架、重构架构或清空数据。
- 问题范围已有明确说明时直接采用；只补变化和缺口，不迫使用户重新经历完整启动问答。
- 先列不应变化的旧行为，再列本次改变；审查调用方、默认值、错误和兼容路径。
- 表/字段、外部契约、权限和定时任务变化逐项说明；没有变化也只在查证后说明。
- 最小切片可局限本次修复，但需包含真实触发路径与相关回归，不能只做单点语法检查。
- 交接更新本次事实、证据和未验证项；历史报告不能当作当前制品的通过证明。

## 九、叠加：LLM / 生成式 AI

**触发**：模型生成、检索增强、工具调用、智能体或自动决策进入本次产品流程。
- 明确 AI 负责建议、草稿还是执行；AI 角色不能替代真实用户研究或有权审批人。
- 定义不可接受输出、人工确认点、失败/超时/拒答/降级行为，不能只测“看起来聪明”。
- 列输入/输出敏感级别、外部传输、日志与留存；不得为了调试默认上传真实个人/商业数据。
- 工具与检索内容是不可信输入；模型输出不直接成为授权、数据库命令或高权限操作。
- 若会执行动作，明确权限最小化、参数校验、审批、幂等与撤销/补偿，防止间接注入扩大权限。
- 选代表性用例与边界/攻击样例建立评测，记录模型、提示、数据与工具版本及成本/时延。
- 检索需核对来源、访问边界、数据时效及失败反馈；引用存在不等于内容正确。
- 真实 API、模型额度和数据调用需要相应授权；可用模拟先验证接线，但不得宣称质量已验证。
- G3 验证关键风险；G4 验证安全闭环；G5 对最终配置评测；G6 说明观察、成本和停用方式。

## 十、叠加：离线 / 同步 / 外设

**触发**：关键任务要断网可用、多设备同步，或依赖打印机、扫码器、蓝牙等硬件。
- 先定义哪些能力离线可用、哪些只能联网、用户如何知道数据新旧与待同步状态。
- 明确数据事实来源、读写策略、冲突规则、队列重试/幂等、删除传播与失败恢复。
- 不自动采用“最后写入覆盖”；冲突会影响业务时需业务负责人确认。
- 验证断网、弱网、进程终止、重启、重复发送、乱序和存储不足等适用场景。
- 外设列型号/协议/固件/连接环境与平台限制；设备不可用就列未验证，不用假设备冒充实测。
- 区分发出命令、设备接收和现实动作完成；付款、打印等结果不明先查询，不能盲重试。
- G3 优先做风险 spike；G4 在目标设备完成核心路径；G5 验证打包后权限/驱动/重连。
- G6 说明配对、诊断、日志脱敏、维护责任及无法恢复时的人工路径。

## 十一、叠加：交易 / 资金 / 库存等强业务约束

**触发**：金额、订单、支付/退款、余额、计费、库存或不可逆业务状态会改变。
- 定义状态机、合法转换、金额/数量单位、精度/舍入及一致性边界，缺失规则请有权者确认。
- 区分“请求已提交”“本地成功”“外部确认”“结果不明”，界面不能把中间态说成完成。
- 设计适用的幂等、并发控制、去重、回调验证、对账和补偿；不能以无限重试掩盖不一致。
- 验证重复点击、超时、回调重放/乱序、部分失败和恢复；恢复不应造成二次扣款/重复库存。
- 真金、真实订单和生产数据测试单独授权；默认使用沙箱与合成数据，不伪造真实成功。
- 退款、权限提升、批量修改、迁移和删除等高影响步骤明确人工审批与审计需求。
- G3 证实一致性方案可行；G4 贯通正确与失败路径；G5/G6 核对对账、告警和恢复责任。

## 十二、叠加：敏感数据 / 受监管场景

**触发**：个人信息、凭据、健康/财务资料、商业机密或有明确监管要求的数据。
- 识别数据类别、目的、必要字段、处理者与流向；只收集实现目标所需的数据。
- 明确访问、导出、日志、备份、留存和删除边界；不能用“用了加密”代替整体风险评估。
- 优先用合成/脱敏材料验证；密钥走既有安全机制，不进入源码、截图、原型或交接文档。
- 传输、存储与模型/第三方调用边界逐项查证；开发环境不自动获得真实数据访问权。
- 法律、行业与地区要求按明确场景查当前权威来源，必要时由具备资格的责任人确认。
- AI 分析不是法律/医疗/合规认证；未知要求保留未验证，不宣称本技能已全行业覆盖。
- G3 处理高风险边界；G5 查制品与日志泄露；G6 说明事件响应、保留与退出责任。

## 十三、裁剪记录与易错检查

先记录 `平台 / 档位及依据 / 交付目标`；能力短表可写 `能力/风险 | 采用/只建议/未验证 | 适用门 | 证据/理由 | 下一步`。持久状态引用 [最小状态索引](documentation-and-operations.md#13-最小状态索引)，不重复定义字段。
- 无 UI：G2 做契约/流程 HTML，不强造业务页面；无登录/无数据库：记录需求依据，不填默认模板。
- 无生产权限：可以交付制品与部署方案，但实际生产发布仍未执行；不猜测“用户应该同意”。
- 只有合成演示：原型或模拟证据如实标注，不能用来通过必须真实集成的门。
- 工具或环境缺失：缩小承诺、保留未验证项；不能改验收标准把失败自动解释为成功。
- 按所选档位增加对应证据；低风险可合并文档/会议，但不能取消 html-mockup、授权或编造证据。
